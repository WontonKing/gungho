## 操作流程

1. 開啟網頁，設定目前年齡、退休年齡、準備金、退休收入與生活費。
2. 在「我的保障」修改初始示範保單，或新增實際保單與正式報價。
3. 在跨公司比較中檢視商品條件與來源；加入商品後補齊契約期限、保費及可領金額。
4. 選擇事故年齡與額外支出，檢視保障缺口、年度現金流及資金變化。
5. 固定方案A，再修改保障或提撥金額，以比較結果。

所有輸入只保留於本次頁面，重新整理即重設。正式商品樣本中未取得報價的保費會標示未知；此時費用與資金結果不完整。初始示範保單的保費、保額及增幅均為模型假設，不能用來比較公司的價格。商品樣本並非市場完整名單。

## 模型與可重現假設

模型每年計算一次，包括目前年齡及規劃終點當年的整年；不處理生日、保單週年或事故月份的精細時點。

- 年保費＝目前年保費 ×（1＋保費年增率）^距今年數；超過繳費或保障末年後停止，末年含當年。可測試非保證續保中斷。
- 退休前提撥為已扣生活費、尚未扣保費的金額，依生活通膨調整；退休後扣生活費與一般醫療費。
- 退休收入以目前購買力輸入，先換算至退休時，再按退休後收入年增率調整；已退休者從現在金額起算。
- 年末準備金＝年初準備金＋正的年初準備金 × 年報酬率＋收入或提撥－生活及一般醫療費－保費－額外事件支出＋給付。
- 生活費依生活通膨、一般醫療費與額外照護費依醫療照顧通膨調整。給付未全面跟隨通膨。
- 醫療／意外費用補償合計以設定的事件費用為上限；癌症一次金可高於事件費用。
- 長照按每月等值金額計算，首年扣設定等待月數，並受給付年數及保障期限限制。單利增額為使用者設定。
- 壽險以債務＋家屬支持費－家屬可用資產計需求，呈現死亡保障缺口，不模擬死亡後現金流。
- 資金小於零表示累積資金缺口；模型不計貸款利息。期末購買力另以生活通膨折算。

模型採固定報酬與單一事故情境，不計事故機率、隨機市場波動、稅負、核保結果、死亡機率或完整理賠規則，也不自動估算勞保／勞退給付。複合保單僅計所輸入的保障部分；長照一次金、免繳保費、癌症安養金、首年限制、公共補助與事件合併等須逐約另行確認。勾選符合理賠條件是情境假設，不表示保險公司必然給付。

## 網頁部署

### GitHub Pages

1. 建立或選定網站儲存庫，將本壓縮檔解壓後的全部檔案上傳至準備發布的資料夾，保留 `.nojekyll`。
2. 依 GitHub Pages 官方說明設定發布來源；入口 `index.html` 必須位於該來源資料夾最上層。
3. 發布完成後使用 Pages 提供的網址開啟。檔案使用相對路徑，也可放在專案子路徑。

官方部署依據：[建立 GitHub Pages 網站](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)（查閱：2026-10-09）。

### 一般靜態網站主機

將 `index.html`、`styles.css`、`model.js`、`data.js`、`app.js` 放到主機相同的公開資料夾，即可由該網址進入。此套件不需要建置命令、伺服器端程式或 API 金鑰。也可先解壓並在瀏覽器開啟 `index.html` 預覽。

可攜套件本身沒有登入機制；登入或存取限制由您選用的主機設定。既有線上版本的存取設定不會自動套用到其他主機。
